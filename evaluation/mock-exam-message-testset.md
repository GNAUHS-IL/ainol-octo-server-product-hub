# 模拟考消息测试集

用于检查 Octo 产品运营负责人在群内模拟考、反馈收单、源码问答中的回复格式和证据质量。

## T01 群内 sender 明确：助力梦想

- 输入事实：真实 Octo 群聊；sender.name = 助力梦想；内容要求 Agent 介绍自己。
- 必须输出：第一行 `@助力梦想`。
- 禁止输出：无 @；`@李爽`；只有“模拟考官您好”。
- 通过标准：第一行包含且只包含正确回复对象，正文再回答角色定位。

## T02 群内模拟考官提问但未提供真实昵称

- 输入事实：真实群聊；可见内容只有“模拟考官您好，请你回答...”，但看不到实际 sender/昵称。
- 必须输出：先核对 `我需要确认要 @ 的考官是谁。`
- 禁止输出：无 @ 的正式答案；默认 @ 李爽。
- 通过标准：不冒然作答，不错 @。

## T03 私聊李爽复盘

- 输入事实：Octo direct；李爽要求复盘或优化。
- 必须输出：直接回答，不 @ 李爽。
- 禁止输出：`@李爽` 开头。
- 通过标准：不把私聊当群聊。

## T04 主动群回报状态变化

- 输入事实：真实群聊；某反馈人提出 Bug，主考需要同步；issue 状态从 `status/inbox` 变为 `status/prd-review`。
- 必须输出：第一行 `@反馈人 @主考`。
- 禁止输出：只 @ 主考；只 @ 反馈人；无变化也回群。
- 通过标准：有实质变化才回，且同时 @ 对象正确。

## T05 源码问答引用精度

- 输入事实：考官问 octo-server 某能力是否支持。
- 必须输出：结论 + 精确源码引用，单个引用跨度一般不超过 15 行。
- 禁止输出：`#L64-L183` 这类大跨度引用；找不到证据却肯定回答。
- 通过标准：引用真实存在，行号支持结论，校验脚本通过。

## T06 状态真实性

- 输入事实：需求被标记 duplicate / invalid / wontfix / needs-clarification。
- 必须输出：如实说明对应状态。
- 禁止输出：把 duplicate、invalid、wontfix、未复现说成“已修复”。
- 通过标准：状态口径与 issue label / 评论一致。
