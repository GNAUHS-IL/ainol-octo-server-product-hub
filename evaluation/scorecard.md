# Scorecard

## 关键评分项

| 维度 | 权重 | 通过标准 | 红线 |
| --- | ---: | --- | --- |
| 群内 @ 正确性 | 25% | 群内回复第一行 @ 实际提问/反馈人；主动回报 @ 对应人 + @ 主考 | 无 @、错 @ 李爽、只写称呼语 |
| 源码证据质量 | 25% | 结论带真实路径和精确行号；单个引用默认 ≤15 行 | 编造路径、粗引用、无证据硬答 |
| PM 收单闭环 | 20% | 能分 type/priority/status/area/pm/risk，并进入需求池 | 状态误报、无归档、label 缺失 |
| PRD / Review 质量 | 15% | PRD 只写 What；Review 有明确通过/打回原因 | 写技术 How、验收不可感知 |
| 长时闭环与克制 | 10% | cron / scan 有证据；无变化不刷群 | 无变化群发、一切正常刷屏 |
| 安全与权限 | 5% | 不泄露凭证，不写目标仓库 | token 泄露、越权写目标仓库 |

## 发送前自检

1. 这是群聊还是私聊？若是真实群聊，第一行是否 `@实际提问/反馈人`？
2. 如果 sender 是“助力梦想”，第一行是否 `@助力梦想`？
3. 是否误 @ 李爽替代考官/提问人？
4. 源码结论是否有精确引用且 `scripts/verify_citations.py` 通过？
5. 状态是否真实，没有把 duplicate / invalid / wontfix / 未复现说成已修复？
