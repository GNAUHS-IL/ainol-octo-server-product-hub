# Octo 群内回复闸门

> 目的：避免群内正式回复漏 @、错 @、误 @ 李爽，确保外部群聊回复对象准确。

## 一句话规则

**真实 Octo 群聊里，谁发消息 / 谁 @ 我 / 谁提问，我回复第一行就必须 `@谁`。**

如果能看到 `sender.name` 或群昵称，默认对象就是该 sender；例如 sender 是“助力梦想”，第一行必须是：

```text
@助力梦想
```

## 发送前三步闸门

### 1. 判定真实场景

不要只看单一 metadata 字段，也不要只看话术。必须综合：

- 当前消息来源；
- 群聊截图；
- 消息 sender / 群昵称；
- 被引用消息；
- 用户明确纠正；
- 当前任务是否发生在真实群聊。

若系统字段与截图、用户纠正冲突，以可见事实和用户纠正为准。

### 2. 锁定 @ 对象

优先级：

1. 当前/被处理的群消息 `sender.name` 或群昵称；
2. 文本、引用、截图里明确 @ 我或要求我回答的人；
3. 当前反馈/提问人；
4. 若仍无法识别，先核对，不发正式答案。

禁止把“服务对象李爽”自动当成群内 @ 对象。李爽只有在本人就是实际提问/反馈人时才可被 @。

### 3. 检查回复第一行

群内正式回复必须满足：

```text
@实际提问人
<正式回复正文>
```

主动群回报必须满足：

```text
@对应人 @主考
<状态变化/结论>
```

## 常见错误与正确写法

| 场景 | 错误写法 | 正确写法 |
| --- | --- | --- |
| 群内“助力梦想”提问 | `您好，...` | `@助力梦想\n您好，...` |
| 群内提问人发起问题 | `您好，...` | `@实际提问人\n您好，...` |
| 不知道真实考官昵称 | 直接发正式答案 | `我需要确认要 @ 的考官是谁。` |
| 私聊李爽复盘 | `@李爽 已处理` | `已处理...` |

## 红线

- 称呼语不是 @。
- 群内不能发送无 @ 的正式答复。
- 不能错 @ 李爽替代考官、提问人或反馈人。
- 不能在不知道 @ 对象时硬发。
- 主动回报不能只 @ 主考，必须同时 @ 对应人。
