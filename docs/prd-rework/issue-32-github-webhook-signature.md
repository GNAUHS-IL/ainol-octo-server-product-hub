# Issue #32 PRD 返工模式：安全鉴权类 PRD 不保留核心规则待确认

## 适用场景
外部 webhook、签名校验、secret、token revoke、权限、审计等安全/鉴权类 PRD。

## 本次问题
PRD 初稿把以下核心规则留作待确认，导致 Review Gate 不可验收：
- 迁移窗口时长与到期策略。
- 签名状态 / delivery 失败原因 / secret 配置重置的可见角色。
- 迁移期豁免在产品文档与审计中的风险标记口径。

## 改进规则
1. 安全/鉴权类 PRD 必须给出确定的迁移窗口、到期行为、延期审批角色和审计记录要求。
2. 涉及管理端状态、失败原因、secret 操作时，必须写清角色权限矩阵。
3. 迁移期豁免不得被写成长期安全状态，必须明确是否满足最终审计要求。
4. 待确认事项不得包含会阻塞验收的产品规则本体；如必须待确认，应保持 issue 在 blocked / rework，而不是推进 reviewing。

## 本次修复口径
- 存量 GitHub webhook 迁移窗口：30 个自然日。
- 到期后行为：未签名、签名格式不符合要求、签名不匹配或 secret 未配置的 GitHub delivery 不得继续投递到群内。
- 延期：仅产品运营负责人或具备 Space 安全管理职责的授权管理员可批准一次性受控延期，需截止时间、原因类别和脱敏审计记录。
- 权限矩阵：区分 Space 管理员、群管理员 / webhook 管理员、webhook 创建者、产品运营负责人 / 授权排障人员、普通成员 / 外部请求方。
- 审计标记：迁移期豁免在产品文档、管理端状态、deliveries / audit 中必须标记为“仅过渡，不满足最终审计要求”。
