# PRD 返工检查：状态回查与异常告警口径防冲突

适用场景：消息送达、投递链路、状态回查、Bot 接收、mention 解析等 PRD。

## 检查项

- 状态词表需与既有投递链路口径对齐，至少明确：待投递、投递中、等待处理、已送达、部分送达、处理成功、失败、投递超时、重试中、已恢复、需人工处理、状态待确认、记录过期。
- “状态待确认 / 记录过期 / 无权查看”只能表示当前不可判定或不可见，不得解释成发送失败、链路故障或已修复。
- 涉及多个目标、多个 Bot、多个 mention 对象时，必须定义“部分送达 / 部分成功 / 部分失败”的展示口径，避免误报整体成功或整体失败。
- “处理成功”必须基于可核验成功结果；仅确认消息可见、已送达或进入待处理时，应展示“已送达 / 等待处理 / 状态待确认”。
- 查询类能力与告警类能力边界要明确：查询不到状态默认不触发异常告警；只有连续失败、超时达到阈值、核心链路无可见状态更新、待处理量持续异常或明确失败证据，才进入告警口径。
- 无权限、跨 Space、不可见 Thread / 会话、Bot ownership 不满足时，只展示安全摘要，不暴露对象是否存在。
