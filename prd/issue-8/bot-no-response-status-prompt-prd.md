# PRD：Bot 无响应时提供明确状态提示

## 1. 背景与问题

客户演示时，Bot 在群里突然不回消息，页面上无法判断是掉线、无权限还是处理中，容易让客户误认为系统故障。

现有能力已经具备 Bot 心跳、独立保活通道、事件等待、权限检查和 BotFather 连接/断开提示等基础。本需求聚焦于把这些状态转译为用户可理解、可恢复、不过度暴露内部细节的状态提示。

- Bot API 已有心跳状态边界。来源: modules/bot_api/bot_api.go#L28-L32
- Bot 心跳失败已有失败提示基础。来源: modules/bot_api/typing.go#L224-L234
- 现有事故注释说明业务流量、心跳、发送等可能相互影响并导致断联体验。来源: modules/bot_api/ratelimit.go#L24-L37
- Bot 事件等待能力支持“有无结果/等待中”的状态基础。来源: modules/bot_api/events.go#L19-L33
- BotFather 已有连接/断开命令入口。来源: modules/botfather/const.go#L31-L36

## 2. 目标与非目标

### 目标

- 用户在群内唤起 Bot 后，不再面对完全沉默的状态。
- 用户能区分至少四类状态：处理中、连接异常或掉线、无权限或不可访问、失败或异常。
- 用户能看到下一步建议：继续等待、稍后重试、补充信息、联系产品运营负责人或由有权限人员重新连接。
- 提示内容支持运营对客户解释，但不泄露 token、Space、内部错误详情或无权对象是否存在。

### 非目标

- 不改变 Bot 当前业务处理范围。
- 不承诺所有异常自动恢复。
- 不新增内部诊断页或后台技术方案。
- 不暴露内部技术细节或凭证明文。

## 3. 用户故事

### US-01：群内用户看到 Bot 无响应状态
- 角色：作为群内提问用户
- 场景：当我在群里唤起 Bot 后长时间没有任何反馈
- 诉求：希望看到 Bot 当前是在处理中、连接异常、无权限还是失败
- 价值：以便我知道继续等待、重试、补充信息还是联系负责人
- 来源: modules/bot_api/events.go#L19-L33

### US-02：运营人员能解释客户演示中的无响应
- 角色：作为产品运营负责人
- 场景：当客户问“系统是不是坏了”
- 诉求：希望看到可对客户解释的状态摘要和下一步建议
- 价值：以便减少误判和现场沟通成本
- 来源: modules/bot_api/ratelimit.go#L24-L37

### US-03：有权限人员看到连接恢复提示
- 角色：作为有 Bot 管理权限的运营或创建者
- 场景：当 Bot 已明确断开连接
- 诉求：希望知道可以重新连接，且无权限用户不会看到敏感连接信息
- 价值：以便安全恢复 Bot 服务
- 来源: modules/botfather/templates/zh-CN/command.tmpl#L67-L70

## 4. 功能需求

### F-01-1 无响应状态提示
- 所属故事：US-01
- 需求描述：当用户在群内明确唤起 Bot 后，如果在合理等待时间内没有任何接收、处理中、失败或完成类反馈，应出现“暂未收到明确响应”的状态提示。
- 业务规则：提示必须说明当前正在确认状态，并给出“继续等待”或“稍后重试”的选择。
- 边界场景：如果系统已能明确判断为掉线、无权限或失败，不应继续展示泛化等待。
- 来源: modules/bot_api/events.go#L19-L33

### F-01-2 处理中与超时等待更新
- 所属故事：US-01
- 需求描述：当 Bot 已接收请求但仍在处理中时，用户应看到“处理中/排队中/等待结果”的中间状态；长时间没有最终结果时，应再次提示仍在等待。
- 业务规则：等待提示不得表达为已完成、已修复或已失败。
- 边界场景：如果任务需要用户补充信息，最多列出 3 个待补充问题。
- 来源: modules/bot_api/events_wait.go#L82-L95

### F-01-3 连接异常或掉线提示
- 所属故事：US-01、US-03
- 需求描述：当 Bot 明确处于连接异常、心跳异常或已断开时，用户应看到可理解的异常提示。
- 业务规则：有管理权限的用户可看到重新连接建议；普通群成员只看到联系产品运营负责人或项目负责人的建议。
- 边界场景：连接提示不得展示 token、连接命令中的敏感参数或内部诊断细节。
- 来源: modules/bot_api/typing.go#L224-L234
- 来源: modules/botfather/templates/zh-CN/command.tmpl#L143-L157

### F-01-4 无权限或不可访问提示
- 所属故事：US-01
- 需求描述：当用户无权操作或查看 Bot 状态时，应看到明确无权限提示和合规下一步。
- 业务规则：提示应表达为“当前账号无权执行此操作或查看该 Bot 状态，请联系本群产品运营负责人或项目负责人确认权限”。
- 边界场景：不得暴露用户无权查看的 Bot、群、Space 或凭证是否存在。
- 来源: modules/bot_api/send.go#L172-L176

### F-01-5 失败或异常原因摘要
- 所属故事：US-02
- 需求描述：当 Bot 无响应最终被归因为失败或异常时，用户应看到可理解的失败摘要和下一步建议。
- 业务规则：失败摘要只展示用户可恢复动作，不展示内部调用链或敏感错误详情。
- 边界场景：如果无法确认原因，应提示“暂无法确认具体原因，请稍后重试或联系负责人”，不得编造结论。
- 来源: modules/bot_api/api_i18n.go#L139-L153

## 5. 状态与提示

- 已接收/处理中：表示请求已进入处理，用户可继续等待。
- 长时间无响应：表示暂未获得明确响应，用户可继续等待或稍后重试。
- 连接异常/掉线：表示 Bot 当前可能无法继续处理，需要有权限人员确认连接。
- 无权限/不可访问：表示当前账号或当前群无权查看或执行，不暴露目标是否存在。
- 失败/异常：表示本次未完成，提供可恢复建议或联系负责人。
- 需补充信息：一次最多列出 3 个问题。

## 6. 验收标准

- AC-01：当用户在群内唤起 Bot 后长时间没有任何反馈，用户能看到明确的无响应状态提示和下一步建议。
- AC-02：当 Bot 仍在处理中，用户能看到处理中状态，且不会被误导为已完成或已失败。
- AC-03：当 Bot 明确连接异常或断开时，有权限用户能看到重新连接建议，普通用户能看到联系负责人的建议。
- AC-04：当用户无权限时，用户能看到无权限提示，但看不到无权对象的敏感细节或凭证明文。
- AC-05：当失败原因可安全展示时，用户能看到可理解摘要；无法安全展示时，用户能看到兜底提示和下一步。

## 8. 待确认事项

- [待确认] “长时间无响应”的默认提示阈值是否采用 30 秒，处理中二次提示是否采用 2 分钟。
- [待确认] 群内无明确产品运营负责人时，提示中的负责人名称采用“本群项目负责人”还是统一引导到运营入口。

## 9. 五类风险检查

- 多租户 / Space 隔离：只展示当前用户、当前群和其有权 Bot 范围内的状态。
- 权限 / ownership：无权限时明确拒绝并给下一步，不引导普通用户重新连接他人 Bot。
- 安全 / 外部输入 / 凭证：不展示 token、cookie、secret、私钥、连接命令敏感参数或内部错误详情。
- 限流 / 防滥用：提示引导等待或稍后重试，避免鼓励刷屏式重试。
- 审计 / 可追溯：涉及人工确认、权限确认或重新连接建议时，应能追溯由谁确认、确认哪个 Bot 和处理结果。
