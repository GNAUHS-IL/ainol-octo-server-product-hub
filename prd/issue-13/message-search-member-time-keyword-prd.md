# PRD：消息搜索支持按成员、时间范围、关键词组合筛选

## 1. 背景与问题

客户群和高频群聊中消息量大，排障人员在出现客户问题、交付异常或上下文争议时，需要快速定位“谁在什么时间说过什么”。仅靠人工翻群消息会显著拖慢客户支持和研发定位效率。

现有消息搜索能力已经有会话内搜索入口，并在进入搜索前执行当前会话可读校验。来源: modules/messages_search/search_messages.go#L60-L67；来源: modules/messages_search/search_messages.go#L77-L83

现有搜索请求模型已具备关键词、发送成员、时间范围、排序、分页等基础检索概念，且空关键词需要至少一个有效筛选条件，避免无约束全量扫描。来源: modules/messages_search/validate.go#L20-L24；来源: modules/messages_search/validate.go#L27-L41；来源: modules/messages_search/validate.go#L214-L220

现有搜索结果包含消息标识、发送人、发送时间、所属会话和命中摘要等展示所需信息。来源: modules/messages_search/search_messages.go#L21-L35

## 2. 目标与非目标

### 目标

- 群/会话内搜索支持按发送成员、时间范围、关键词组合筛选。
- 本周最小版本仅覆盖群/会话内搜索，不纳入全局搜索。
- 排障人员可以在大群历史消息中快速定位关键上下文。
- 组合筛选结果必须继续遵守当前用户对会话、thread、DM、群消息的可读权限。
- 搜索结果必须让用户看清发送人、发送时间、所属会话、消息标识和命中摘要。
- 分页和排序稳定，连续翻页不重复、不丢失。
- 删除、撤回、当前不可见消息不得通过组合筛选返回。
- 文档说明筛选条件、时间口径、排序、分页、权限边界和空关键词口径。

### 非目标

- 不做复杂高级搜索语法。
- 不做跨产品搜索。
- 不做全局搜索组合筛选；全局搜索作为后续可做项。
- 不做前端复杂筛选器重构。
- 不做语义搜索或向量搜索。
- 不做导出全量聊天记录。
- 不绕过现有权限体系。
- 富文本、文件、转发消息本期沿用现有搜索类型边界，不新增深度解析或跨类型重构。
- 不承诺本期一次覆盖所有消息类型深度内容解析。

## 3. 用户故事

### US-01：客户群排障人员按成员、时间和关键词定位上下文
- 角色：作为交付 / 客服 / 运维 / 研发排障人员
- 场景：当客户群出现问题，需要定位某位成员在某段时间内提到的关键内容
- 诉求：希望用成员、时间范围和关键词组合筛选消息
- 价值：以便快速找到关键上下文，减少人工翻找时间
- 来源: modules/messages_search/swagger/api.yaml#L28-L40

### US-02：普通群成员按条件缩小搜索范围
- 角色：作为当前仍具备会话可读权限的群成员
- 场景：当群内消息量很大，单纯关键词搜索结果过多
- 诉求：希望进一步按发送成员和时间范围缩小结果
- 价值：以便更快找到自己有权查看的目标消息
- 来源: modules/messages_search/validate.go#L20-L24；来源: modules/messages_search/validate.go#L27-L41

### US-03：产品运营和支持人员确认搜索边界
- 角色：作为产品运营负责人或客户支持人员
- 场景：当用户询问组合搜索为什么没有返回某些消息
- 诉求：希望文档明确空关键词、时间范围、成员多选、排序、分页和权限边界
- 价值：以便对用户给出一致解释，避免把权限过滤误判为搜索异常
- 来源: modules/messages_search/swagger/api.yaml#L331-L344；来源: modules/messages_search/swagger/api.yaml#L346-L360

## 4. 功能需求

### F-01-1 组合筛选
- 所属故事：US-01、US-02
- 需求描述：用户在指定群或会话中搜索时，可以同时使用关键词、发送成员和时间范围筛选消息。
- 业务规则：同时指定多个条件时，结果必须同时满足所有条件；未指定某类条件时，不应对该类条件额外限制。多成员筛选确认为“任一选中成员命中”。
- 边界场景：本期允许“成员 + 时间范围”在空关键词下组合浏览；关键词、成员、时间范围三者全空不允许；仅成员或仅时间默认不放行，需研发性能评估后再由产品复核。
- 来源: modules/messages_search/validate.go#L20-L24；来源: modules/messages_search/validate.go#L27-L41

### F-01-2 成员筛选
- 所属故事：US-01、US-02
- 需求描述：用户可以选择一个或多个发送成员作为筛选条件，只查看这些成员发送的命中消息。
- 业务规则：多成员筛选建议按“任一选中成员命中”处理；成员标识或成员状态异常时，不得扩大结果范围。
- 边界场景：传入空成员、无效成员、当前用户不可见成员或超出数量上限时，应给出明确结果或提示，不得退化为无成员限制的宽搜；仅成员筛选默认不放行，需研发性能评估后再由产品复核。
- 来源: modules/messages_search/validate.go#L88-L99；来源: modules/messages_search/validate.go#L105-L112

### F-01-3 时间范围筛选
- 所属故事：US-01、US-02
- 需求描述：用户可以选择起止时间范围，只查看该范围内的命中消息。
- 业务规则：时间范围口径必须对用户清晰，包括使用的时间类型、时区、起止边界是否包含。
- 边界场景：开始时间晚于结束时间、时间格式不合法、跨时区展示不一致时，用户应获得明确提示；仅时间范围筛选默认不放行，需研发性能评估后再由产品复核。
- 来源: modules/messages_search/validate.go#L114-L128

### F-01-4 权限与可见性一致
- 所属故事：US-01、US-03
- 需求描述：组合筛选结果必须与当前用户消息读取权限一致。
- 业务规则：无权访问的群、thread、DM 或当前不可见消息不得出现在搜索结果中；新增筛选条件不得绕过后端权限判断。
- 边界场景：权限、成员状态、删除/撤回/清空会话等可见性判断失败时，应按安全方式处理，不得直接返回底层命中。
- 来源: modules/messages_search/search_messages.go#L71-L83；来源: modules/messages_search/visibility.go#L195-L209；来源: modules/messages_search/visibility.go#L216-L221

### F-01-5 结果展示
- 所属故事：US-01、US-02
- 需求描述：搜索结果需要展示足够信息，帮助用户判断结果属于哪条消息和哪个会话上下文。
- 业务规则：每条结果至少应让用户看到发送人、发送时间、所属会话、消息标识和命中摘要。
- 边界场景：命中摘要不可用时，应有可理解的降级展示；不得展示用户当前不可见内容。
- 来源: modules/messages_search/search_messages.go#L21-L35

### F-01-6 排序与分页稳定
- 所属故事：US-01、US-02
- 需求描述：组合筛选支持稳定分页，连续翻页不重复、不丢失。
- 业务规则：默认排序和相关性排序的口径需在文档说明；相同时间的多条消息也应保持稳定顺序。
- 边界场景：大量结果、相同时间或连续翻页时，用户不应看到重复、跳页或明显乱序；富文本、文件、转发消息沿用现有搜索类型边界。
- 来源: modules/messages_search/dsl.go#L130-L144；来源: modules/messages_search/dsl.go#L161-L171；来源: modules/messages_search/dsl.go#L172-L185；来源: modules/messages_search/dsl.go#L424-L432

### F-01-7 文档与测试覆盖
- 所属故事：US-03
- 需求描述：补充组合搜索的使用说明、验收样例和权限边界说明。
- 业务规则：文档需覆盖关键词、成员、时间范围、空关键词口径、时间格式、时区、排序、分页和权限边界。
- 边界场景：文档不得引导用户通过构造参数绕过权限，也不得暴露内部敏感信息。
- 来源: modules/messages_search/swagger/api.yaml#L28-L40；来源: modules/messages_search/swagger/api.yaml#L331-L344；来源: modules/messages_search/swagger/api.yaml#L346-L360

## 5. 状态与提示

- 有结果：用户看到符合组合条件且当前有权查看的搜索结果。
- 无结果：用户看到当前条件下没有可见结果，而不是误以为搜索失败。
- 条件无效：用户看到哪个筛选条件不合法，例如时间格式、时间顺序或成员数量。
- 无权限或不可见：用户看不到不可读会话或不可见消息；提示不得暴露目标对象是否存在。
- 结果过多：用户可继续缩小成员、时间或关键词条件，并通过分页稳定浏览。
- 系统异常：用户获得明确失败提示，不返回未经可见性确认的底层命中。

## 6. 验收标准

- AC-01：当用户在指定群/会话内输入关键词时，能看到当前有权查看的命中消息。
- AC-02：当用户指定一个发送成员时，结果只包含该成员发送且当前用户有权查看的命中消息。
- AC-03：当用户指定多个发送成员时，按 OR 口径返回这些成员中任一成员发送且当前用户有权查看的命中消息。
- AC-04：当用户指定时间范围时，结果只包含发送时间落在该范围内且当前用户有权查看的命中消息。
- AC-05：当用户同时指定成员、时间范围和关键词时，结果同时满足三类条件。
- AC-06：当不指定成员时，系统不额外限制发送人；当不指定时间范围时，系统不额外限制时间。
- AC-07：当关键词为空时，本期允许“成员 + 时间范围”组合浏览；关键词、成员、时间范围三者全空不允许；仅成员或仅时间默认不放行，需研发性能评估后再由产品复核。
- AC-08：当前用户无权访问的群、thread、DM 或当前不可见消息不会出现在结果中。
- AC-09：伪造会话、thread、space 或成员范围相关输入不能绕过后端权限校验。
- AC-10：删除、撤回、当前用户已清空或当前不可见消息不会出现在结果中。
- AC-11：每条搜索结果都能让用户识别发送人、发送时间、所属会话、消息标识和命中摘要。
- AC-12：相同时间下连续翻页稳定，不重复、不丢失、不明显乱序。
- AC-13：自动化测试覆盖仅关键词、成员 + 时间空关键词组合、成员 + 时间 + 关键词三者组合、无权限会话、分页稳定、删除/撤回不可见；仅成员和仅时间默认不放行的口径也需覆盖。
- AC-14：文档说明筛选条件、时间格式、时区、分页规则、排序规则、空关键词口径、全局搜索非本期范围和权限边界。

## 9. 五类风险检查

- 多租户 / Space 隔离：组合筛选不得扩大 Space、群、thread、DM 的可读范围；无权对象不得因筛选条件被召回。
- 权限 / ownership：所有搜索结果必须以当前操作者的会话可读权限和消息可见性为准；伪造范围条件不能绕过后端判断。
- 安全 / 外部输入 / 凭证：搜索关键词可能包含敏感信息，日志和文档不得记录明文敏感内容。
- 限流 / 防滥用：成员、时间、关键词组合查询不应允许无约束全量扫描；异常高频搜索应继续受限。
- 审计 / 可追溯：排障场景需要能追溯搜索行为的安全摘要，但不得记录明文敏感关键词或不可见消息内容。
