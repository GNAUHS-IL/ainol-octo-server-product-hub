# PRD：Bot/Agent 无响应时的用户可见状态与恢复提示

## 1. 背景

用户在 Octo 群内唤起 Bot/Agent 后，可能遇到长时间无响应的情况。此时用户无法判断反馈是否已被受理，也无法区分当前是等待处理、连接异常、无权限，还是服务暂时不可用。

现有产品中已经存在 Bot/Agent 连接、断开、失败重试、重新连接等用户可见动作和文案基础，因此本需求聚焦于把“无响应时用户能看到什么、下一步该做什么”补齐为一致的产品体验。

## 2. 目标用户

- 在 Octo 群内使用 Bot/Agent 的普通用户。
- 负责处理群内反馈、需求归档、PRD 与 Review 的产品运营人员。
- 需要判断 Bot/Agent 当前是否可用的管理员或项目负责人。

## 3. 用户目标

用户希望在 Bot/Agent 长时间无响应或连接异常时，能看到明确、可理解、可执行的状态提示，知道当前反馈是否被接收，以及下一步应该等待、重试、补充信息、联系负责人，还是重新连接。

## 4. 产品范围

### 本次包含

- 用户在群内唤起 Bot/Agent 后，如果长时间没有获得处理结果，应看到清晰状态提示。
- 状态提示需要区分至少以下情况：等待处理中、连接异常、无权限、服务暂时不可用、需要用户补充信息。
- 失败或异常提示必须包含下一步建议，例如等待、重试、重新连接、联系产品运营负责人或补充必要信息。
- 对于已经明确断开连接的场景，用户应能看到断开结果和重新连接入口提示。
- 对于用户无权限的场景，用户应能看到明确的无权限说明，而不是沉默无响应。
- 对于信息不足的场景，提示最多给出 3 个需要补充的问题。

### 本次不包含

- 不改变 Bot/Agent 的业务处理范围。
- 不承诺所有异常都能自动恢复。
- 不包含内部技术方案、系统改造细节或上线方案。
- 不包含新建管理后台页面。

## 5. 用户故事

作为在 Octo 群内提交反馈的用户，我希望 Bot/Agent 无响应时能看到明确状态和下一步建议，以便判断我的反馈是否被受理，并知道该等待、重试还是联系负责人。

## 6. 用户流程

1. 用户在 Octo 群内唤起 Bot/Agent 或提交反馈。
2. 用户等待处理结果。
3. 如果 Bot/Agent 在合理时间内没有给出最终结果，用户看到状态提示。
4. 用户根据提示选择继续等待、重试、补充信息、重新连接或联系负责人。
5. 用户获得成功、失败、无权限或待人工处理的明确结果。

## 7. 交互与文案要求

- 成功时：提示用户反馈已被接收或处理完成，并说明下一步状态。
- 等待中：提示“正在等待处理，请稍后；若长时间无结果，可重试或联系负责人”。
- 连接异常时：提示“当前 Bot/Agent 连接可能异常，请稍后重试或按提示重新连接”。
- 失败时：提示失败原因的用户可理解摘要，并给出下一步建议。
- 信息不足时：最多列出 3 个需要用户补充的问题。
- 无权限时：明确提示用户当前无权限，并说明应联系谁确认权限。
- 人工复核确认时：说明当前问题需要产品运营负责人确认，不把待确认状态说成已完成。

## 8. 验收标准

### 用户可见验收

- [ ] 用户在群内唤起 Bot/Agent 后，如果长时间无响应，能看到明确状态提示。
- [ ] 操作完成、失败或异常时，用户能在 3 秒内看到可理解的结果提示。
- [ ] 失败时，用户能看到原因摘要和下一步建议。
- [ ] 断开连接后，用户能看到已断开的结果和重新连接提示。
- [ ] 用户不会只看到沉默无响应，而无法判断反馈是否被受理。

### 边界条件验收

- [ ] 当用户无权限时，能看到明确无权限提示和权限确认建议。
- [ ] 当用户输入不完整时，能看到最多 3 个需要补充的问题。
- [ ] 当状态仍在等待处理中时，提示不会把等待说成成功或失败。
- [ ] 当需要人工确认时，提示不会把待确认说成已完成。
- [ ] 用户可以重试、等待或联系负责人，不会卡死在无反馈状态。

### 安全与隐私验收

- [ ] 敏感凭证不会展示在群聊、日志或 issue 中。
- [ ] 用户只能看到自己有权限看到的信息。
- [ ] 错误提示不暴露内部细节或敏感上下文。

## 9. 非目标范围

- 本需求不定义内部方案细节。
- 本需求不承诺替代人工处理所有异常。
- 本需求不改变现有 Bot/Agent 权限边界。
- 本需求不要求展示内部诊断信息。

## 10. 风险与待确认问题

1. 需要产品运营负责人确认“长时间无响应”的用户可接受阈值。
2. 需要确认哪些群聊场景允许提示用户重新连接，哪些场景只提示联系负责人。
3. 需要确认无权限提示中应展示的联系人或处理入口。
