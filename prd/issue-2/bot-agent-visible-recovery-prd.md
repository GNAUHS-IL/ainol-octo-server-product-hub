# PRD：Bot/Agent 无响应时的用户可见状态与恢复提示

## 1. 背景

用户在 Octo 群内唤起 Bot/Agent 后，可能遇到长时间无响应的情况。此时用户无法判断反馈是否已被受理，也无法区分当前是等待处理、连接异常、无权限，还是服务暂时不可用。

现有产品中已经存在 Bot/Agent 连接、断开、失败重试、重新连接等用户可见动作和文案基础，因此本需求聚焦于把“无响应时用户能看到什么、下一步该做什么”补齐为一致的产品体验。

## 2. 目标用户

- 在 Octo 群内使用 Bot/Agent 的普通用户。
- 负责处理群内反馈、需求归档、PRD 与 Review 的产品运营人员。
- 需要判断 Bot/Agent 当前是否可用的管理员或项目负责人。

## 3. 用户目标

用户希望在 Bot/Agent 等待、断联、连接异常、无权限、服务暂时不可用或信息不足时，能看到明确、可理解、可执行的状态提示，知道当前反馈是否被接收，以及下一步应该等待、重试、补充信息、联系负责人，还是重新连接。

## 4. 产品范围

### 本次包含

- 用户在群内唤起 Bot/Agent 后，如果在定义的等待阈值内没有获得处理结果，应看到清晰状态提示。
- 状态提示需要区分至少以下情况：等待处理中、连接异常、已断开连接、无权限、服务暂时不可用、需要用户补充信息。
- 失败或异常提示必须包含下一步建议，例如等待、重试、重新连接、联系产品运营负责人或补充必要信息。
- 对于已经明确断开连接的场景，用户应能看到断开结果和重新连接入口提示。
- 对于用户无权限的场景，用户应能看到明确的无权限说明和可执行的权限确认入口。
- 对于信息不足的场景，提示最多给出 3 个需要补充的问题。

### 本次不包含

- 不改变 Bot/Agent 的业务处理范围。
- 不承诺所有异常都能自动恢复。
- 不包含内部技术方案、系统改造细节或上线方案。
- 不包含新建管理后台页面。

## 5. 用户故事

作为在 Octo 群内提交反馈的用户，我希望 Bot/Agent 无响应时能看到明确状态和下一步建议，以便判断我的反馈是否被受理，并知道该等待、重试、重新连接、补充信息还是联系负责人。

## 6. 产品状态规则

### 6.1 “长时间无响应”的触发阈值

- 用户在群聊中明确唤起 Bot/Agent 后，如果 30 秒内没有看到任何接收、处理中、失败或完成类提示，应视为“长时间无响应”，必须出现用户可见状态提示。
- 如果用户已看到“处理中/排队中/待人工确认”等中间状态，但 2 分钟内仍没有看到最终结果或下一步提示，应再次提示当前仍在等待，并给出重试或联系负责人的选择。
- 如果系统已能明确判断 Bot/Agent 已断开、无权限、服务暂时不可用或信息不足，则不等待上述阈值，应直接给出对应状态提示。

### 6.2 下一步建议场景边界

- 提示“继续等待”：适用于已明确接收用户请求、当前仍在处理中，且没有失败、无权限或断联结论的场景。
- 提示“稍后重试”：适用于服务暂时不可用、处理失败但用户可以重新发起的场景。
- 提示“重新连接”：仅适用于用户正在管理自己创建或有管理权限的 Bot/Agent，且产品已明确展示该 Bot/Agent 处于断开连接或连接信息需要重新获取的场景。
- 提示“联系产品运营负责人”：适用于用户没有权限、当前群聊不允许用户自行重新连接、权限归属不清、或系统无法确认应由谁继续处理的场景。
- 提示“补充信息”：适用于用户输入不足以继续处理的场景，且一次最多列出 3 个必须补充的问题。

### 6.3 无权限提示的处理入口

- 无权限时，用户应看到明确提示：“当前账号无权执行此操作或查看该 Bot/Agent 状态”。
- 无权限提示必须给出下一步：“请联系本群产品运营负责人或项目负责人确认权限”。
- 若当前会话中存在明确的产品运营负责人身份，应优先提示联系产品运营负责人；否则提示联系本群项目负责人。
- 无权限提示不得暴露用户无权查看的 Bot/Agent、群、Space、token 或内部诊断信息。

## 7. 用户流程

1. 用户在 Octo 群内唤起 Bot/Agent 或提交反馈。
2. 用户等待处理结果。
3. 如果 30 秒内没有任何接收、处理中、失败或完成类提示，用户看到“正在确认 Bot/Agent 状态”的提示。
4. 如果已经有处理中提示但 2 分钟内仍没有最终结果，用户看到“仍在处理中”的更新提示，并获得继续等待、重试或联系负责人的建议。
5. 如果状态已明确为断开、无权限、服务暂时不可用或信息不足，用户直接看到对应原因和下一步建议。
6. 用户根据提示选择继续等待、重试、重新连接、补充信息或联系负责人。
7. 用户获得成功、失败、无权限或待人工处理的明确结果。

## 8. 交互与文案要求

- 成功时：提示用户反馈已被接收或处理完成，并说明下一步状态。
- 等待中：提示“已接收，正在处理中；如果超过 2 分钟仍没有结果，可重试或联系产品运营负责人确认”。
- 30 秒无任何反馈时：提示“暂未收到 Bot/Agent 明确响应，正在确认状态；你可以继续等待，或稍后重试”。
- 已断开连接时：提示“当前 Bot/Agent 已断开连接；如你有管理权限，可按连接提示重新连接，否则请联系产品运营负责人”。
- 连接异常时：提示“当前 Bot/Agent 连接可能异常，请稍后重试；如持续失败，请联系产品运营负责人确认”。
- 失败时：提示失败原因的用户可理解摘要，并给出下一步建议。
- 信息不足时：最多列出 3 个需要用户补充的问题。
- 无权限时：提示“当前账号无权执行此操作或查看该 Bot/Agent 状态；请联系本群产品运营负责人或项目负责人确认权限”。
- 人工复核确认时：说明当前问题需要产品运营负责人确认，不把待确认状态说成已完成。

## 9. 验收标准

### 用户可见验收

- [ ] 用户在群内唤起 Bot/Agent 后，如果 30 秒内没有任何接收、处理中、失败或完成类提示，能看到明确的无响应状态提示。
- [ ] 用户已看到处理中提示后，如果 2 分钟内仍没有最终结果或下一步提示，能看到仍在等待的更新提示。
- [ ] 操作完成、失败或异常时，用户能在 3 秒内看到可理解的结果提示。
- [ ] 失败时，用户能看到原因摘要和下一步建议。
- [ ] 断开连接后，用户能看到已断开的结果，并能判断自己应重新连接还是联系负责人。
- [ ] 用户不会只看到沉默无响应，而无法判断反馈是否被受理。

### 边界条件验收

- [ ] 当用户无权限时，能看到明确无权限提示，并知道应联系本群产品运营负责人或项目负责人确认权限。
- [ ] 当用户不具备 Bot/Agent 管理权限时，提示不会引导其自行重新连接。
- [ ] 当用户具备管理权限且 Bot/Agent 已明确断开时，提示包含重新连接建议。
- [ ] 当当前群聊不允许用户自行重新连接，或权限归属不清时，提示引导联系产品运营负责人。
- [ ] 当用户输入不完整时，能看到最多 3 个需要补充的问题。
- [ ] 当状态仍在等待处理中时，提示不会把等待说成成功或失败。
- [ ] 当需要人工确认时，提示不会把待确认说成已完成。
- [ ] 用户可以重试、等待、补充信息或联系负责人，不会卡死在无反馈状态。

### 安全与隐私验收

- [ ] 敏感凭证不会展示在群聊、日志或 issue 中。
- [ ] 用户只能看到自己有权限看到的信息。
- [ ] 错误提示不暴露内部细节或敏感上下文。
- [ ] 无权限提示不暗示用户无权查看对象是否存在，也不展示 token、Space 或内部诊断信息。

## 10. 非目标范围

- 本需求不定义内部方案细节。
- 本需求不承诺替代人工处理所有异常。
- 本需求不改变现有 Bot/Agent 权限边界。
- 本需求不要求展示内部诊断信息。

## 11. 风险与约束

- 权限边界：无权限时要明确提示下一步，但不能暴露用户无权查看的信息。
- 敏感信息：异常提示、日志和需求单不得展示敏感凭证。
- 防滥用：提示应引导用户有序等待、重试或联系负责人，避免反复刷屏。
- 状态真实性：等待、失败、无权限、待人工确认不能混成“已完成”。
- 多租户隔离：任何状态提示只能基于当前用户、当前群聊和其有权访问的 Bot/Agent 信息，不展示其他 Space 或会话的信息。
- 审计可追溯：涉及人工确认、权限确认或重新连接建议时，用户应能知道下一步由谁确认，不在公共提示中展示敏感凭证。

## 13. 证据

- Bot API 中存在 heartbeat 相关状态边界，心跳过期时间为 60 秒，可支撑“断联/心跳状态需要被用户感知”的产品背景。来源: modules/bot_api/bot_api.go#L28-L32
- BotFather 中存在同类 heartbeat 状态边界，说明 Bot 管理体验里已有连接状态相关概念。来源: modules/botfather/const.go#L26-L28
- BotFather 已提供 `/connect` 与 `/disconnect` 命令，说明用户侧存在重新获取连接信息和断开连接的操作入口。来源: modules/botfather/const.go#L31-L36
- BotFather 命令集中包含 Bot 管理相关入口。来源: modules/botfather/const.go#L37-L50
- 现有断开连接文案已告知 Agent 会被踢下线、待处理内容会被清空，并提示使用 `/connect` 重新获取连接信息。来源: modules/botfather/templates/zh-CN/command.tmpl#L65-L70
- 帮助文案已向用户展示 `/connect`、`/disconnect` 等 Bot 管理命令。来源: modules/botfather/templates/zh-CN/command.tmpl#L122-L136
- 帮助文案也包含待处理申请、通过、拒绝、取消和帮助等操作入口。来源: modules/botfather/templates/zh-CN/command.tmpl#L137-L141
- 连接信息文案会展示 Bot 连接所需信息，因此相关提示必须避免向无权限用户泄露敏感凭证。来源: modules/botfather/templates/zh-CN/command.tmpl#L143-L157
- 连接文案还提示断开连接入口，说明连接/断开是用户可见动作。来源: modules/botfather/templates/zh-CN/command.tmpl#L158-L161
- Bot token 获取路径要求调用者与 Bot 创建者一致，并要求 Bot 属于调用者绑定的 Space，支撑无权限提示和多租户隔离要求。来源: modules/bot_provision/bot_api.go#L96-L109
- Bot token 获取路径在调用者不是 Bot 创建者时拒绝，且不泄露对象是否存在，支撑反枚举和脱敏提示要求。来源: modules/bot_provision/bot_api.go#L157-L166
