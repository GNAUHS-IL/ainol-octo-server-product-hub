# PRD：支持群聊 Bot 消息发送后的送达状态回查

## 1. 背景与问题

Issue #17 反馈：Bot 主动向群聊发送消息后，当前调用方主要拿到消息编号，不方便确认消息是否真正进入目标群、@mention 是否正确解析、目标会话 / 群聊是否符合预期，以及目标 Bot 是否收到或为何未收到。这会增加运营、测试和考试模拟排障成本。

现有源码显示，Bot 发送入口已存在目标、频道类型、内容、权限、群状态、群成员关系和 Space 成员关系等发送前校验；发送完成后当前直接返回发送结果，测试注释也说明发送响应只带 消息编号，后续需要另行等待消息序号就绪；同时，群聊 mention 已存在服务端透传、@所有 AI 展开、Bot 成员枚举、Bot 事件读取等基础。因此本需求重点定义“按消息编号回查后，运营能看到哪些状态、哪些解析结果、哪些失败/不可确认原因、谁能查、保留多久”，不定义内部实现方案。

关联口径：本需求与 #15「消息投递链路异常自恢复与失败告警」共用投递链路状态语言，但边界不同：#17 只描述按消息编号回查到的当前可判定事实；“状态未知 / 记录过期”只能表示当前不可判定，不等同于失败，也不能单独触发链路故障告警。

- Bot API 发送入口已挂载在 Bot 鉴权范围内，并受业务限流约束。来源: modules/bot_api/bot_api.go#L400-L410
- Bot 发送会校验目标会话 / 群聊、会话类型和消息内容。来源: modules/bot_api/send.go#L53-L70
- Bot 发送前会执行发送权限检查。来源: modules/bot_api/send.go#L172-L176
- Bot 群聊发送会检查群状态、群成员关系和不可用群。来源: modules/bot_api/send.go#L503-L537
- 发送完成后当前直接返回发送结果。来源: modules/bot_api/send.go#L426-L446
- 现有测试注释说明发送响应只带 消息编号，编辑前需要再等待消息序号就绪。来源: modules/bot_api/card_p2_edit_im_test.go#L7-L10
- mention 透传规则明确保留 mention.all、mention.humans、mention.ais、mention.uids 和 mention.entities。来源: pkg/mentionrewrite/rewrite.go#L23-L39

## 2. 目标与非目标

### 目标

- 支持按消息编号回查 Bot 主动发送群聊消息后的送达状态。
- 回查结果能展示目标会话 / 群聊 信息、发送状态、mention 解析结果、目标 Bot 接收状态和失败 / 不可确认原因。
- 状态口径必须区分“已接收发送请求、发送中、已进入目标群、mention 已解析、目标 Bot 已可见 / 已进入待处理、失败、不可确认、记录过期”等事实，不把未确认说成成功。
- 查询范围和权限边界清晰：只能查询当前调用方有权 Bot、目标群 / 会话、所属 Space 范围内的消息状态。
- 记录保留时长和过期提示明确，过期后仍给出可理解说明。
- 对权限、目标不存在、跨 Space、Bot ownership、限流和内部异常等敏感场景做脱敏提示，不帮助枚举无权对象。
- 支持运营、测试和产品负责人用一致状态口径排查“消息没进群 / @没生效 / Bot没收到 / 目标错了 / 状态待确认”。

### 非目标

- 不定义内部技术方案、数据结构或部署方案。
- 不改变现有 Bot 发送、群成员、Space、OBO 或 Bot ownership 权限边界。
- 不承诺所有消息都能得到最终成功结论；无法确认时必须显示“状态待确认”。
- 不提供跨 Space、跨 Bot、跨群的全量消息审计入口。
- 不展示消息正文、token、cookie、secret、私钥、内部调用链、内部错误堆栈或无权对象详情。
- 不替代 Bot 业务处理结果；本需求只说明消息送达 / mention / 接收链路状态，不判断 Bot 业务是否正确完成。

## 3. 用户故事

### US-01：运营按消息编号确认群消息是否进入目标群

- 场景：当 Bot 主动向群聊发送消息后，只拿到消息编号但不确定是否真正进入目标群
- 诉求：希望按消息编号看到发送状态、目标会话 / 群聊 和当前可确认结论
- 价值：以便快速判断是发送失败、目标错误、群不可用还是状态仍待确认
- 来源: modules/bot_api/send.go#L426-L446；来源: modules/bot_api/card_p2_edit_im_test.go#L7-L10

- 场景：当消息包含 @具体成员、@所有人、@所有 AI 或 Bot mention 后，目标对象没有预期反应
- 诉求：希望看到 mention 解析是否成功、解析出的目标类型和异常原因
- 价值：以便区分 mention 格式错误、目标不可见、Bot 成员为空、被权限限制或状态待确认

- 场景：当群消息已发送但目标 Bot 没有响应
- 诉求：希望看到目标 Bot 是否被识别、是否处于可接收范围、是否有待处理事件或不可确认原因
- 价值：以便决定继续等待、重试、检查 Bot 状态或联系负责人

## 4. 功能需求

### F-01-1 按消息编号回查发送状态
- 所属故事：US-01、US-04
- 需求描述：系统应支持有权限调用方按消息编号查询 Bot 主动发送群消息后的当前状态。
- 业务规则：查询结果至少说明：消息编号是否可识别、是否属于当前有权 Bot / channel 范围、目标会话 / 群聊是否可见、当前状态、最近更新时间、下一步建议。
- 状态口径：至少包含“已接收发送请求、发送中、已进入目标群、状态待确认、失败、不可查询、记录过期”。如能确认 Bot 处理链路，可补充“目标 Bot 已可见 / 已进入待处理 / 已处理”。
- 边界场景：消息编号为空、格式不符合要求、找不到记录、记录过期或无权限时，应给出安全提示；无权限场景不得泄露目标消息、群、Space 或 Bot 是否存在。
- 来源: modules/bot_api/send.go#L53-L70；来源: modules/bot_api/send.go#L426-L446

### F-01-2 目标会话 / 群聊 信息展示
- 所属故事：US-01、US-04
- 需求描述：回查结果应展示调用方有权看到的目标会话 / 群聊 信息，帮助确认消息是否发往预期群聊或子区。
- 业务规则：有权范围内至少展示 channel 类型、可识别名称或脱敏标识、当前可访问状态；无权范围只展示“无权查看或目标不可访问”的安全提示。
- 边界场景：群已解散、群不存在、Bot 不在群内、调用方不在所属 Space、目标会话 / 群聊 与消息编号不匹配时，应明确提示可恢复动作或联系负责人，不得扩大可见范围。
- 来源: modules/bot_api/send.go#L503-L537；来源: modules/bot_api/authtree_guard.go#L17-L45

### F-01-3 mention 解析结果展示
- 所属故事：US-02、US-03
- 需求描述：当消息包含 mention 时，回查结果应展示 mention 是否被识别、识别到的目标类型和处理结论。
- 业务规则：mention 结果至少区分“无 mention、指定成员 mention、@所有人、@所有 AI、混合 mention、mention 格式异常、目标不可见、状态待确认”。对于 @所有 AI，应能说明是否识别到可触达的 Bot 成员数量或安全摘要。
- 边界场景：mention 目标为空、目标不在群内、目标已离开、Bot 成员为空、mention 格式异常、解析结果过多或超出可展示范围时，应展示可理解原因；不得向无权限调用方列出完整成员清单。
- 来源: pkg/mentionrewrite/rewrite.go#L23-L39；来源: modules/bot_api/send.go#L391-L413；来源: modules/bot_api/mention_expand.go#L16-L45

### F-01-4 目标 Bot 接收状态
- 所属故事：US-03
- 需求描述：当消息目标涉及 Bot mention、@所有 AI 或群内 Bot 接收时，回查结果应展示目标 Bot 是否可被识别、是否在有权接收范围内、是否进入待处理或状态不可确认。
- 业务规则：仅对当前调用方有权查看的 Bot 展示接收状态；普通调用方只看到安全摘要。状态至少包含“未涉及 Bot、Bot 已识别、已进入待处理、已处理、未进入待处理、Bot 不在可接收范围、状态待确认”。
- 边界场景：Bot 已断开、未加入群、无群权限、被限流、事件读取尚未返回、处理方异常或记录过期时，应给出安全原因分类和下一步建议。
- 来源: modules/bot_api/events.go#L54-L66；来源: modules/bot_api/events.go#L37-L52；来源: modules/bot_api/events.go#L302-L316

### F-01-5 失败原因与不可确认原因分类
- 所属故事：US-01、US-04
- 需求描述：查询失败或状态异常时，系统应返回运营可理解的原因分类和下一步建议。
- 业务规则：至少覆盖：消息编号无效、无权查看、目标会话 / 群聊 不可访问、Bot 无群权限、群已解散、目标 Bot 不可达、mention 目标不可见、被限流、记录过期、内部异常兜底、状态待确认。
- 边界场景：涉及权限、Space、Bot ownership、目标不存在或内部异常时，只展示脱敏摘要，不暴露可用于枚举或攻击的信息。
- 来源: modules/bot_api/send.go#L172-L176；来源: modules/bot_api/send.go#L503-L537；来源: modules/bot_api/authtree_guard.go#L42-L45

### F-01-6 查询范围与权限边界
- 所属故事：US-01、US-03、US-04
- 需求描述：查询能力必须限定在调用方有权范围内，不允许用消息编号跨 Bot、跨群、跨 Space 探测消息、成员或 Bot 是否存在。
- 业务规则：Bot 调用方只能查询自己发送或被授权管理的消息；Space 管理员或产品运营负责人只能在其有权 Space / 群 / Bot 范围内查看；无权用户统一得到安全拒绝或不可访问提示。
- 边界场景：当调用方只知道 消息编号 但无权访问对应目标时，不返回目标群名、成员、Bot 名称、Space 信息或消息正文；当权限状态变化后，查询结果必须以当前可见权限为准。
- 来源: modules/bot_api/events.go#L62-L66；来源: modules/bot_api/authtree_guard.go#L17-L45

### F-01-7 记录保留时长与过期提示
- 所属故事：US-01、US-04
- 需求描述：产品应明确送达状态回查记录的保留时长，首版建议默认保留最近 7 天，并在页面或文档中说明超过保留期后无法保证可回查。
- 业务规则：保留期内按权限展示可确认状态；超过保留期展示“记录已过期 / 无法确认历史状态”的提示，并建议用户用发送时间、目标群和消息编号补充排查信息。
- 边界场景：因合规、安全、容量或运营策略需要调整保留期时，应对用户展示当前生效口径；过期不得误报为消息不存在或发送失败。
- 来源: modules/bot_api/events.go#L268-L277；来源: modules/bot_api/events.go#L279-L316

### F-01-8 状态口径文档与排障说明
- 所属故事：US-01、US-02、US-03、US-04
- 需求描述：文档或产品说明应列出状态枚举、mention 结果、权限边界、保留期、常见失败原因和建议动作。
- 业务规则：运营可据此向测试或用户解释“为什么只显示待确认”“为什么看不到目标详情”“为什么 @所有人 不等于 @所有 AI”。
- 边界场景：文档不得暴露内部实现、内部日志原文、凭证明文或无权对象详情。
- 来源: pkg/mentionrewrite/rewrite.go#L23-L39；来源: modules/bot_api/send.go#L391-L413

## 5. 状态与提示

- 已接收发送请求：系统已收到发送动作，但不代表目标群或目标 Bot 已处理。
- 发送中：系统正在确认消息进入目标会话 / 群聊 的状态。
- 已进入目标群：在调用方有权范围内，可确认消息已进入目标群 / 会话。
- mention 已解析：消息中的 mention 结构已被识别，并可展示安全摘要。
- 目标 Bot 已可见 / 已进入待处理：可确认目标 Bot 已被识别或已有待处理线索。
- 处理成功：可确认目标 Bot 对该消息完成了对应处理；仅在有事实依据时展示。
- 失败：可确认发送、解析或接收链路失败，并给出脱敏原因分类。
- 状态待确认：当前无法确认最终成功或失败，需继续等待、补充信息或联系负责人；不得解释为发送失败或链路故障。
- 无权查看：当前调用方无权查看该消息或目标对象详情。
- 记录过期：超过保留期，无法保证可回查历史状态；不得解释为发送失败或链路故障。

## 6. 验收标准

- AC-01：当有权限调用方输入有效消息编号时，能看到该消息的当前发送状态、目标会话 / 群聊 安全摘要、最近更新时间和下一步建议。
- AC-02：当群聊消息包含指定成员 mention 时，有权限调用方能看到 mention 是否识别成功、目标是否在可见范围内，以及异常时的脱敏原因。
- AC-03：当群聊消息包含 @所有 AI 时，有权限调用方能看到 Bot 目标识别结果或“未识别到可触达 Bot / 状态待确认”的安全摘要。
- AC-04：当目标 Bot 已进入待处理或已处理时，有权限调用方能看到对应状态；无法确认时不得显示为成功。
- AC-05：当消息编号不存在、记录过期、目标不可访问或调用方无权时，用户能看到安全提示和下一步建议，不暴露无权对象是否存在。
- AC-06：当群已解散、Bot 不在群内、目标 Bot 不可达、mention 目标不可见、被限流或内部异常时，查询结果能展示运营可理解的失败 / 不可确认分类。
- AC-07：记录保留期口径在产品说明中可见；超过保留期时显示“记录过期 / 无法确认历史状态”，不误报为发送失败，也不因查询不到状态而误触发链路故障告警。
- AC-08：状态说明文档覆盖查询范围、状态枚举、mention 口径、权限边界、保留期和安全提示。
